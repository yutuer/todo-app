## 1. 技术形态

- **单文件**：`index.html` 一个文件装下 HTML + CSS + JS，无构建、无打包、无 npm 依赖。

### 3.1 失败根因（重要，勿重犯）

1. **外部脚本注入法不可靠**。codex 后续改用独立的 `.py` / `.js` 脚本读取 HTML，做 `content.replace(锚点, 新内容)` 再写回。**锚点只要有一处对不上，`replace` 就静默返回原串**，脚本照样打印 `Done`，文件却零改动——看起来成功了，实际什么都没发生。
   - 实证：脚本锚定 `initCalendar();`，而本文件的实际初始化函数叫 `renderCalendar();`，该锚点从未存在。
2. **脚本源文件编码错乱**。`add_quick_final.py` 里的中文「快捷语」被写成 `¿ì½ÝÓï`，即使在正确锚点插入也会产出乱码。
3. **用字符串拼 `innerHTML` + 内联 `onclick` 渲染动态内容**。配合手写转义 `escapeHtml(t.text).replace(/'/g, "\\'")`，任务文本里一出现引号、反斜杠、尖括号就容易整块渲染失败。

**规避方式：直接在 `index.html` 里就地编辑（见第 5 节锚点表），动态 DOM 一律用 `createElement` + `textContent` + `addEventListener`，不拼 `innerHTML`，不写内联 `onclick`。**

**TODO-8　侧栏吸顶**：根因是**吸顶做在了错误的层级**——`.calendar-card` 单独 `position: sticky`，而快捷语面板是它的**兄弟节点**，没有 sticky，所以滚动时日历钉住、面板走掉。

五套皮肤：`cartoon` 卡通风 / `cyber` 赛博朋克 / `robot` 机器人 / `anime` 二次元 / `ink` 水墨。

**实现要点**：
- 皮肤 CSS 内联主文件，`body[data-skin="xxx"]` 覆盖 12 个设计变量 + 各皮肤签名样式

### 4.8 顺延逻辑扩口径（`0403b40`）

**Bug**：主人报「线上看不到今日之前建立的未完成待办」。

**根因**：`getGroupedTodos()` 用 `x.date === yesterday` 只匹配**昨天一天**。任务建在 10/17 或更早 → 永不匹配 → 永不顺延。旧逻辑对照实验：喂 3 条（昨天 / 前日 / 远期），只顺延 1 条，**漏 2 条**。

**修复**：
```js
// 旧：只认昨天
const yesterday = getYesterdayKey();
todos.filter(x => x.date === yesterday && !x.completed && currentFilter === 'all')

// 新：今天之前任意日期的未完成，移走式
if (t.date < today && !t.completed) { carried.push({...t, isContinued: true, originDate: t.date}); return; }
```

| 设计点 | 决定 |
|---|---|
| 重复处理 | **移走式**——原日期分组不再单独渲染，避免同一条出现两次 |
| 来源标注 | 「来自 &lt;原日期&gt;」+ 创建时间（原「来自昨天」已不适用） |
| 已完成旧任务 | **不顺延**，留在原日期分组作为记录 |
| `currentFilter` | `completed` 走早返回分支不顺延；`active` 下未完成项本就全保留，逻辑自然一致 |
| 排序 | 顺延项按原日期升序排在前，同日建的聚在一起 |

**验证方式（值得复用）**：沙箱内 Playwright 连不上本机 8080（网络命名空间隔离），改用 **Node 单元测试**——用正则从 `index.html` 抽出 `getGroupedTodos` **真实源码**再喂数据跑断言，测的是真代码而非复刻品。4 场景 11 断言全 PASS。**逻辑类改动优先用此法，比浏览器测试更严谨且不受环境限制。**

**部署注意**：`git push` 后线上 build 戳仍显示旧 SHA，等约 45 秒才变新。**推完不等于生效**，必须 `sleep` 后复检 `curl ... | grep build-stamp`。

**教训**：臣妾第一轮排查只抓了「昨天」一个日期分组，看到顺延生效就断言"功能无 bug"——**实际漏掉了 10/17 的任务**。去查 bug 必须构造**跨多天 / 已完成与未完成 / 各筛选态**的边界数据，碰巧命中一条就收工比不查更糟，因为它会让主人以为已经修好。

### 4.9 localStorage 兼容层（`normalizeTodo`）

**问题**：第 8 节早就写明「修改 `todos_v3` 的数据结构前务必做向后兼容（旧数据读入时补默认字段），否则用户已有的任务会丢」，但 `loadTodos()` 一直只是裸 `JSON.parse`，**没有任何补全**。后果：

1. 旧记录缺 `date` → `t.date` 为 `undefined`，`getGroupedTodos()` 里 `t.date < today` 得 `false`，于是归组键变成字面量 `"undefined"`，页面上多出一个日期为 `NaN月NaN日` 的分组。
2. 顶层不是数组 / JSON 损坏 → `todos` 变成对象或字符串，后续 `todos.filter` 直接抛错，**整个应用不可用**。
3. **相邻同源隐患**：`collapsedDates` 那行原本是 `new Set(JSON.parse(localStorage.getItem(COLLAPSED_KEY) || '[]'))`，**存储值一旦损坏，这行直接抛异常中断整个 `<script>`**——后面所有事件绑定与渲染都不执行，**全站白屏**。

**修法**：
- 新增 `normalizeTodo(raw)`：逐字段补默认值——`id` 缺失则 `generateId()`；`text` 非字符串则转字符串、为空则丢弃该条；`date` 非 `YYYY-MM-DD` 则回落今天；`createdAt` 缺失则补 `Date.now()`；`completed` 非 `true` 一律视为 `false`；`completedAt` 仅在已完成时保留。
- `loadTodos()` 改为：解析失败 / 顶层非数组 → 空数组；逐条 `normalizeTodo` 后 `filter(Boolean)` 丢弃无法修复的脏条目。
- **仅当真的发生修正时才回写** `localStorage`（`JSON.stringify` 比对前后），正常数据**不被无谓改写**。注意回写必须发生在 `todos` 赋值**之后**，否则 `saveTodos()` 写的是旧值。
- 新增 `loadCollapsed()`：解析失败 / 顶层非数组 / 含非字符串元素 → 一律回落空集合，**不再让单行异常拖垮整站**。

**保留原则**：只丢弃「彻底无法修复」的条目（`null`、数字、字符串、数组、空 text）。`text` 与 `date` 齐全的旧记录**一律保留**，只是补齐缺失字段——**用户已有任务不丢**。

**同轮加固（自测时发现的两处自身缺陷，已修）**：

1. **回写不得抹掉未知字段**。`normalizeTodo()` 最初只返回 6 个已知字段，一旦触发回写，旧数据里其他字段（未来版本新增的、或用户自带的）会被静默删除——这与 §8「否则用户已有的任务会丢」相悖。改为在返回对象上**保留 `TODO_FIELDS` 之外的原始字段**。
2. **幂等判定不能用整串 `JSON.stringify` 比对**。`addTodo()` 写入的记录**本就没有 `completedAt` 这个键**，若按键集合/键序比较，每个线上用户首次打开都会被判为「有差异」而触发一次无谓回写。改为新增 `sameTodo()` **逐字段语义比较**，并把 `completedAt` 的「缺失」与「null」视为等价。

**验证方式**：

## 4.10 标签系统（全局标签表 + 拖放到任务）

**需求**（2026-10-21 主人提）：照抄 Aurora Board 的标签体系，但本项目没有看板，所以改成「把标签**拖到某个待办事项**上」；并且**改全局标签的文字、删全局标签时，事项里的标签要跟着改 / 移除**。

### 数据模型（沿用 Aurora Board 的核心决策）

| | 值 |
|---|---|
| 全局标签表 | `labels_v1` → `[{id, name, color}]`，**独立于 `todos_v3` 存储** |
| 事项侧 | `todo.labels` → **标签 id 数组**（存 id，**不存名称**） |
| 渲染时 | 按 id 去标签表现查名称与颜色 |

**为什么事项只存 id**：标签是"可被引用的实体"而不是枚举常量。改名 / 改色只改标签表一处，不必遍历改写每一条事项；只有删除标签时才批量清理引用。id 保持不变 → 改名后引用不断。

### 交互

| 操作 | 行为 |
|---|---|
| 侧栏「标签」卡片 | 位于快捷语面板下方；折叠态存 `label_collapsed`；每行 = 色块 + 名称 + 改 / 删 |
| 改 | 打开编辑区（名称输入 + 20 色预设板 + 原生取色器），**改名与改色即时生效**，事项上的标签立刻跟着变；「撤销」回滚到打开时的样子 |
| 新增 | 「+ 添加标签」→ 同一条编辑区；重名 / 空名会被拦下并就地提示 |
| 删除 | **两步确认**：点「删」→ 面板里展开确认条（提示"正被 N 个任务使用"）→ 再点「删除」才真删。**不用原生 `confirm()`**：嵌入式浏览器里它可能被自动 dismiss（点了没反应），样式也和整套皮肤不搭 |
| **拖放** | 从侧栏标签行**按住拖到任务上** → 任务高亮 → 松手即加上该标签 |
| **筛选** | **点标签行 = 只看带该标签的事项**（再点一次取消）；与「全部 / 进行中 / 已完成」**取交集**。筛选中时该行高亮，主区筛选条出现「标签：xxx ×」可一键取消 |
| 事项内的标签 | 渲染成彩色 chip，**右侧有 `×`** → 只移除**本事项**这一条引用，不动全局标签表 |
| 级联删除 | 删全局标签 → 遍历所有事项移除该 id → 回写 `todos_v3` |

### 关键实现决定

1. **标签 chip 用 DOM API 渲染**：`createElement` + `textContent` + `addEventListener`，不拼 `innerHTML`、不写内联 `onclick`（§6 禁止事项第 3 条）。`render()` 之后额外跑一遍 `renderItemLabels()`。
2. **拖放用 HTML5 原生 API**：`dragstart` 写 `dataTransfer`；任务容器上用**事件委托**处理 `dragover`（**必须 `preventDefault`**，否则浏览器不触发 `drop`）/ `dragleave` / `drop`。`dragleave` 要用 `relatedTarget` 判断是否真的离开了那个任务，否则在任务内部移动也会误清高亮。
3. **`normalizeTodo()` 已扩展**：补 `labels` 字段（非数组 / 含非字符串 → 清洗），并把 `labels` 加进 `TODO_FIELDS`。
4. **`sameTodo()` 已扩展**：**数组必须逐元素比较**——用 `!==` 比的是引用，两个内容相同的数组也会被判为"有差异" → 每次打开页面都触发一次无谓回写。另外「键缺失」等价于「空数组」，否则旧数据首次打开就会被回写一次。
5. **浅色阈值取 185**（同 Aurora Board）：只有确实很浅的底色才改用深色字，其余维持白字。
6. **`loadLabels()` 的一处刻意修正**：键存在且是数组就用它，**哪怕是空数组**。Aurora Board 那版写的是 `d.length` 判定，用户把标签删光后下次打开又会被内置标签填回来。
7. **面板临时状态落库**（`label_ui_v1`）：正在编辑哪个标签、待确认删除哪个标签都存起来，刷新页面后编辑框与确认条还在，不会"填了一半就没了"。
8. **`改` / `删` 按钮常驻**（默认半透明、hover 变实），不用 `display:none`——那样键盘用户根本 Tab 不到。
9. **每行显示该标签的事项计数**（`(3)`，为 0 时变淡）。顺带告诉用户哪些标签值得筛，也让人一眼看出拖放有没有生效。
10. **点标签行 = 切换筛选**：用 `mousedown` 与 `click` 的坐标差（> 4px）判断"这是拖动不是点击"，避免**刚拖完标签就误把筛选打开**。
11. **筛选是纯视图状态，不改动数据**：`getGroupedTodos()` 里在状态筛选之后再按标签过滤一次，两个条件**取交集**；被筛掉的事项既不显示也不参与顺延。
12. **筛选状态落库**（`label_ui_v1.filter`）：刷新页面后仍记得你在看哪个标签。筛选状态**始终显示在界面上**（侧栏行高亮 + 主区「标签：xxx ×」），不存在"看不见的隐藏状态"。
13. **删掉正在被筛选的标签 → 筛选自动失效**（`doDelete()` 里清 `labelFilter`；`loadLabelUI()` 也会校验标签是否还存在）。

## 4.11 分组显示顺序（今天置顶 + 未来近的在前）

**问题**（2026-10-22 主人提）：「将今天的事项置顶吧，否则放在最后面看不见」。

**根因**：分组原本是**纯按日期倒序**排的（`dateKeys.sort((a, b) => b.localeCompare(a))`）。只要存在**未来日期**的分组（"下个月交报告"这种），它们就会排到今天前面 —— 于是**今天和近期的分组被压到列表最下面**。主人那边就是这个场景：改动前顺序是 `12月21日 → 10月29日 → 今天`，今天确实在最末尾。

而且只把今天置顶还不够：未来分组内部若是"越远越靠前"，**近期的任务同样会被远期的挡住**（`12月21日` 排在 `10月29日` 上面）。

**现在的规则**（`sortDateKeysForDisplay()`）：

| 顺序 | 分组 | 理由 |
|---|---|---|
| 1 | **今天** | 永远置顶 |
| 2 | 未来日期，**近的在前** | 越近到期越紧急，越该先看见 |
| 3 | 过去日期，近的在前 | 最近的历史在前（这一条原本就是对的） |

**实现**：抽成独立函数 `sortDateKeysForDisplay(keys, today)`，不依赖 DOM，**可以直接对它写断言**；`render()` 只调它。用 `keys.slice().sort(...)` 而不是原地 `sort`，避免副作用。

**验证**：

- **Node 单测**：抽真实源码跑，断言覆盖「有未来分组时今天在最前」「未来近的在前」「无今天分组时的整体顺序」「只有今天」「空数组」「不改动原数组」，全 PASS。
- **浏览器实点**：用临时种子页（`_v.html`，已 gitignore）注入「今天 / +7 天 / +60 天 / 昨天遗留未完成」四条数据，实际渲染顺序为 **今天 → 10月29日（下周）→ 12月21日（两个月后）** ✓

> ⚠️ 注意：`isPastDate()` 决定某组是否显示"折叠提示"，与这里的排序是两件事，别混。

### Step 3　提交
`feat: xxx` / `fix: xxx`，一次提交只做一件事，便于 `git revert` 精准回滚。**不要 `git add .`**（会带入第 7 节的垃圾文件）。

### Step 4　发布与验证

`git push origin main` → 等待 Actions 完成（约 1 分钟）→ 访问 https://yutuer.github.io/todo-app/ 确认根路径正常、功能可用。

**判断"有没有真的更新"，看页脚构建戳**：格式 `SHA7 - MM-DD HH:MM UTC`，由 `deploy.yml` 在 checkout 后注入。戳里的 SHA 与 `git rev-parse --short HEAD` 一致，才说明线上就是本次版本。

**看不到新版本时的排查顺序（三步，别跳）**：

1. `git rev-parse --short HEAD` 与 `git rev-parse --short origin/main` —— 先确认**推没推**
2. `curl -s https://yutuer.github.io/todo-app/ | grep build-stamp` —— 看**线上实际内容**（`curl` 不受浏览器缓存影响）
3. 看响应头 `Cache-Control` / `Last-Modified` —— GitHub Pages 的 HTML 是 `max-age=600`（10 分钟），走 Fastly CDN；**F5 不会绕过缓存**，要 Ctrl+F5，或直接开 `<url>/?v=<时间戳>`

> 教训（2026-10-18）：主人反馈"Ctrl+F5 后仍是旧版"，臣妾第一步先怀疑"是不是没推送"，实际推送与部署都正常。**要按上面三步查证据再下结论，不要顺着"是不是你没推"的方向走**——缓存、本地预览面板、错误 URL，都比"没推送"更常见。

### Step 5　出问题先回滚
`git revert <提交>` 优先于 `git reset --hard`（保留历史）。除非要彻底丢弃一批实验性提交，否则不使用 reset。

### Step 6　收尾（本地预览或自动化测试之后）

三件事都要做，少一件就留残留：

1. **停掉本地服务**。`python -m http.server` 不关，端口会一直被占用，下次起服务要么换端口、要么报 `Address already in use`。核对：`netstat -ano | grep LISTENING | grep :80`
2. **关掉自动化浏览器**。注意语义差异：`page.close()` 只关**标签页**，不等于关**窗口**；以桌面窗口消失为准，不以"没有打开标签"为准。
3. **删临时校验文件**。`_c.js` / `_v.js` / `_v.html` 已在 `.gitignore` 内，但仍应清掉，避免越堆越多。
